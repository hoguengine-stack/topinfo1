## 2. 최종 결론

**전체 판정: 재작업. 현재 상태로 프로덕션 시각 품질 통과 불가.**

새 제품 시스템은 이전의 단일 이미지 교체 방식에서 벗어나 제품별 사용 흐름을 HTML/CSS로 설명하고, 데스크톱 탭과 모바일 선택기, 명확한 상담 CTA를 제공한다. 방향은 개선되었다. 그러나 제품·서비스 사실성, 출처 증거, 실물 비율, 모바일 가독성, 최신 스크린숏이 동시에 충족되지 않았다.

특히 섹션의 공개 문구인 “제품 이미지는 등록된 공식·검증 에셋을 사용했습니다”는 현재 사실보다 강한 표현이다. 실제 구현에는 재구성 Toss POS 화면, `uplus/README.md`에 출처가 없는 IP-520GA 파일, 생성 로봇, 생성 CCTV 모니터링 화면이 포함된다. 이 문구는 증거 확보 전 공개하면 안 된다.

### 4.2 제품 비율 계산

문서에 기록된 실물 제원:

- POSBANK APEXA X-1500: `364 × 210 × 333 mm`
- Toss Front: `147.5 × 128 × 193.5 mm`
- AHAPOS CPP-3000: `130 × 178 × 140 mm`

새 POS 장면의 CSS는 APEXA 래퍼 폭 68%, Toss Front 이미지 폭 28%를 사용한다. 투명 여백을 제외한 원본 경계와 APEXA 마스크 범위를 적용하면 다음처럼 추정된다.

| 비교 | 실물 목표 | 데스크톱 코드 추정 | 모바일 코드 추정 | 판정 |
| --- | ---: | ---: | ---: | --- |
| Front/APEXA 가시 폭 | `147.5/364 = 0.405` | 약 `0.381` | 약 `0.358` | Front가 약 6~12% 작음 |
| Front/APEXA 가시 높이 | `193.5/333 = 0.581` | 약 `0.492` | 약 `0.461` | Front가 약 15~21% 작음 |

이는 렌더 전 코드·알파 경계 기반 추정이다. 정확한 최종 판정은 동일 바닥선, 동일 원근, 동일 픽셀/mm 비율을 표시한 새 스크린숏으로 확인해야 한다. 현재 `product/README.md`의 “same-plane compositions use these heights instead of eyeballed scale” 규칙과 CSS 배치가 일치한다고 볼 수 없다.

### 4.3 새 구현에서 지켜진 점

- 제품 종류별 장면을 분리했고, 인터넷·AI전화·CCTV를 공유기 한 장으로 반복하지 않는다.
- 설명 문구를 이미지에 굽지 않고 HTML로 구성해 한글 깨짐과 수정 난이도를 줄였다.
- 데스크톱 탭, 모바일 선택기, 키보드 포커스, reduced-motion 전환 처리가 있다.
- 커스텀 이미지는 `object-fit: contain`이어서 강제 `cover` 잘림은 줄었다.
- 제품별 CTA가 상담 또는 AI전화 상세 페이지로 연결된다.

이 항목들은 구현 방향의 장점이며 **시각 통과 증거를 대신하지 않는다**.

## 9. 업종별 미디어 감사

실제 비디오 파일(`mp4`, `webm`)은 없다. 자동 재생되는 것은 animated WebP 또는 APNG이다. 확인된 애니메이션은 12개이며, 정적 `*-static.webp`는 첫 프레임 파생본이다. 자동 재생은 기본값으로 유지할 수 있으나 `prefers-reduced-motion`에서는 정적 프레임으로 교체해야 한다. 현재 README는 사이트 전환만 줄이고 제품 애니메이션은 계속 재생한다고 명시해 접근성 기준과 충돌한다.

## 13. 중복·미사용·거버넌스 결함

1. `public/assets`에는 공개 래스터 이미지 97개가 있고, 같은 공식 원본의 정적 프레임·구형 크롭·합성본이 다수 공존한다.
2. 코드 문자열 참조 횟수는 실제 렌더 사용을 의미하지 않는다. 마이그레이션 이력과 deprecated 목록에도 경로가 남아 있기 때문이다.
3. `apexa-x-package-spec-corrected.png`, `toss-pos-screen-exact.png`, `toss-pos-screen.webp`, `uplus-ai-phone-ip520g.jpg`는 현재 직접 공개 경로로 쓸 이유가 없다.
4. `feature-cafe-kiosk*`는 `sector-cafe*`와 같은 원본의 중복 파생이다.
5. `sector-beauty-*` 구형 크롭은 현재 기능별 뷰티 미디어와 중복된다.
6. `generated/system-*`은 새 HTML 시스템 장면과 중복되며 CMS 이력에서 다시 살아날 수 있다.
7. `HOME_SYSTEM_GRAPHICS`는 “표준 자산” 목록에 포함되지만 일부가 생성·재구성 자산이다. 표준과 공식은 같은 뜻이 아니다.
8. Toss, LG U+ 자산 README 모두 프로덕션 공개 전 파트너 재배포 허가 확인을 요구한다. 현재 허가 증빙 파일은 감사 범위에서 확인되지 않았다.
9. U+ IP-520GA 두 파일은 U+ README의 공식 출처 표에 빠져 있다.
10. `sector-retail-apexa-x.webp`의 README 설명은 실제 파일 내용과 다르다. 파일은 빈 계산대 배경이며 APEXA X·Toss Front·스캔 결과는 코드가 추가한다.

## 16. 감사 요약

현재 자산은 “있다”는 수준에서는 풍부하지만, 공개 영업 사이트의 증거로 쓰기 위한 **사실성·모델 일치·권리·실물 비율·반응형 증명**이 부족하다. 가장 위험한 패턴은 공식 원본, 공식 원본의 재구성, 생성 이미지, 임시 합성을 같은 신뢰 수준으로 표시하는 것이다.

새 제품 시스템은 정보 구조와 CTA는 개선됐지만, 그 안에 들어가는 자산과 문구의 신뢰 수준을 엄격히 구분하지 못했다. 따라서 이 섹션은 “구현 완료”가 아니라 **재심사 대기 상태**로 기록한다.
