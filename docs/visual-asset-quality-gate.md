# 시각 자산 품질 게이트

제품 및 UI 이미지는 아래 항목을 모두 통과하기 전까지 `완료`로 보고하지 않는다.

## 1. 출처와 사실성

- 제품 모델명, 공식 제원, 공식 원본 URL을 먼저 기록한다.
- 생성형 이미지는 배경과 조명 보조에만 사용한다. 제품 형상, 로고, UI 텍스트, 상태값, 수량은 공식 원본 또는 코드 합성으로 만든다.
- 공식 원본은 SHA-256과 픽셀 규격을 잠근다. 값이 달라지면 자동 생성이 실패해야 한다.

## 2. UI 의미 일치

- 화면 문구를 추정하지 않는다. 공식 화면에서 확인된 문자열만 사용한다.
- 주문 품목 수량 합계와 결제 버튼의 총 수량이 일치해야 한다.
- 문자열과 상태값은 원본 URL·수집일·원본 해시가 있는 승인 원장에 기록된 값만 사용한다. 이전 합성본의 문자열을 승인값으로 재사용하지 않는다.
- 현재 프로젝트가 별도 검증한 결제 총 수량 `6`도 공식 화면의 주문 품목과 같은 장면임이 확인될 때만 유지한다.
- 제품 기능과 무관한 화면, 아이콘, 장면은 사용하지 않는다.

## 3. 제품 및 합성 품질

- 실제 제원 비율을 기준으로 장비 크기를 맞춘다. 허용 오차는 동일 원근 기준 ±3%다.
- 흰 사각 배경, 마스킹 잔상, 관통, 겹침, 부유, 다른 광원과 그림자 방향이 없어야 한다.
- 로고 위치, 제품 색상, 버튼, 용지 배출구 등 식별 요소가 실제 모델과 일치해야 한다.

## 4. 확대 검수

- 최종 사용 크기와 400% 확대 크기에서 각각 확인한다.
- 텍스트 깨짐, 잘림, 이중 테두리, 낮은 해상도, 이전 이미지 잔여 픽셀이 하나라도 있으면 반려한다.
- 제품 화면은 물리 패널 네 모서리를 모두 채워야 하며, `contain` 여백이나 기존 배경 노출이 있으면 반려한다.
- 반복 이미지, 업종과 맞지 않는 이미지, 초상권 및 재배포 출처가 불명확한 이미지는 반려한다.

## 5. 사이트 반영 검수

- 컴포넌트가 중간 산출물이 아닌 검증본만 참조하는지 검색한다.
- 자산 교체 후 사용자 브라우저를 조작하지 않고 터미널 Playwright/headless 브라우저로 실제 사용 슬롯을 확인한다.
- 최소 `390x844`, `1440x900`, `2560x1440`에서 전체 실루엣, 크롭, 오브젝트 비율, 텍스트 선명도, 상하좌우 여백을 캡처한다.
- 코드 빌드 성공을 시각 품질 통과로 간주하지 않는다.

## 6. 승인 체계

- `구현됨`, `기술 검증됨`, `시각 검수 통과`, `배포 후보`를 구분한다.
- 문제를 발견하지 못했다는 이유로 통과시키지 않는다. 체크리스트와 캡처 근거가 있어야 PASS다.
- 사실성, 제품 비율, 반응형, 접근성 중 하나라도 실패하면 시각 검수 통과로 표시하지 않는다.
- 세부 절차와 점수 기준은 `.agents/skills/topinfo-design-review/SKILL.md`를 따른다.

`node scripts/build-verified-pos-screen.cjs`와 결과물 `public/assets/product/toss-pos-screen-verified.png`는 재구성 이력 확인용이다. 제품 증거로 공개하지 않는다. 로컬 프리뷰는 토스플레이스 공개 페이지에서 추출한 `toss-pos-screen.webp`를 사용하며, 프로덕션 전에는 파트너가 제공한 고해상도 원본과 재배포 허가로 교체해야 한다.
