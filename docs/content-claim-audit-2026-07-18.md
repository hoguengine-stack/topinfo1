# TOPINFO 공개 콘텐츠 주장·CTA 감사

- 감사일: 2026-07-18
- 대상 저장소: `C:\탑정보통신-작업-관리`
- 대상 범위: `src` 전체의 공개 사이트 문구, 공개 CTA, 공개 폼과 접수 후 처리 흐름
- 선행 검토 문서: `AGENTS.md`, `DESIGN.md`, `CONTENT.md`, `REFERENCE.md`
- 변경 범위: 이 감사 문서만 생성했으며 소스 코드는 수정하지 않음

## 1. 결론

현재 공개 사이트에는 공식 자료로 뒷받침되는 제품 기능과 사용자 제공 사업 정보가 상당수 있다. 그러나 다음 네 종류는 운영 공개 전에 바로 정리해야 한다.

1. 실제 실적처럼 보이는 임의 수치: `오늘 문의 18건`, `AI 응대율 94%` 등
2. 값이 없을 때 자동으로 노출되는 `0원` 가격
3. 조건이 빠진 `무료`, `24시간`, `긴급출동`, `설치·AS`, `안산·경기권 지원` 표현
4. Firestore 접수와 작업관리 일감 생성을 같은 단계로 설명한 문구

활성 상담·용지 배송 폼은 Firestore `addDoc`이 성공한 뒤에만 성공 화면을 표시한다. 따라서 **실제 저장 없이 성공 메시지를 표시하는 문제는 현재 활성 폼에서 발견되지 않았다.** 다만 공개 문구는 접수 즉시 작업관리 일감이 자동 생성되는 것처럼 설명하고 있으며, 실제 구현은 관리자가 접수함에서 수동으로 작업을 등록한다. 이 설명은 즉시 수정해야 한다.

## 2. 판정 기준

| 분류 | 기준 |
|---|---|
| 유지 가능(사용자 제공 또는 공식 자료로 검증) | 사용자가 명시적으로 제공한 사업 사실이거나 현재 공식 제품 자료에서 동일한 의미를 확인함 |
| 조건부 표현으로 수정 | 핵심 기능은 사실이지만 가입 상품, 요금제, 장비, 설정, 지역, 비용, 재고 또는 시점 조건이 빠짐 |
| 공개 화면에서 숨김 | 출처가 없거나 임의 수치·가격·후기·혜택이며 방문자가 실제 실적이나 확정 조건으로 오인할 가능성이 큼 |
| 사업자 확인 필요 | 코드와 공식 제품 자료만으로 TOPINFO의 실제 계약 범위, 영업 정책, 서비스 지역, 비용 또는 권리를 확정할 수 없음 |

### 출처 우선순위

1. 사용자가 직접 제공한 TOPINFO 사업 정보
2. 제조사·서비스 제공자의 현재 공식 제품 페이지와 가이드
3. 계약서, 파트너 확인서, 요금표, 설치 정책 등 TOPINFO 내부 사업 문서
4. 현재 코드의 기본값과 CMS 문구

코드에 문구가 존재한다는 사실만으로 사업 주장이 검증되지는 않는다.

## 3. 감사 방법과 한계

- `src` 전체에서 `무료`, `무상`, `24시간`, `직계약`, `공식`, `최고`, `최저`, `가격`, `혜택`, `할인`, `지원`, 설치 지역, 가격·건수·비율·속도 등의 수치, 토스 및 LG U+ 관계 문구를 검색했다.
- 공개 렌더러, 공개 페이지 기본값, 마이그레이션 문자열, 관리자 편집 기본값, 테스트와 비사용 레거시 컴포넌트를 구분해 확인했다.
- 활성 공개 폼의 저장 코드와 백오피스의 작업 등록 코드를 함께 확인했다.
- Firestore에 이미 저장된 CMS 문구는 정적 소스 검색만으로 전부 확인할 수 없다. 운영 전에는 Firestore의 `cms_pages`, 상품 및 설정 문서를 별도로 내보내 같은 규칙으로 재감사해야 한다.
- 이미지의 재사용 권리와 파트너 로고 사용 권리는 코드만으로 확정할 수 없다.

### 비공개 코드에 남은 위험 문구

`BackConsultations.tsx`, `WebAdmin.tsx`, `WebForms.tsx`, `TopWebsite.tsx`의 일부 문구는 현재 공개 라우트가 아니거나 관리자 전용이다. 그러나 CMS 기본값, 재사용 컴포넌트, 작업 메모로 다시 공개되거나 실제 운영 약속으로 사용될 수 있으므로 공개 여부와 별개로 사업 정책 확인 후 정리해야 한다.

## 9. 폼과 성공 상태 감사

| 폼 | 실제 저장 | 성공 표시 시점 | 판정 |
|---|---|---|---|
| 공개 상담 신청 | `consultations` 컬렉션에 `await addDoc(...)` | 저장 성공 후 `setSubmitState("success")` | 통과. 저장 실패 시 오류와 전화번호 표시 |
| 공개 용지 배송 요청 | `paper_requests` 컬렉션에 `await addDoc(...)` | 저장 성공 후 성공 패널 | 통과. 저장 실패 시 오류 표시 |
| 공개 건의 등록 | `suggestions` 컬렉션에 `await addDoc(...)` | 저장 성공 후 닫기/초기화 | 통과 |
| 공개 자료 등록 | `resources` 컬렉션에 `await addDoc(...)` | 저장 성공 후 완료 처리 | 통과 |
| 레거시 `WebForms.tsx` 상담·용지 폼 | 각각 Firestore `addDoc` 대기 | 저장 성공 후 성공 화면 | 성공 순서는 통과. 다만 무상·무료 문구 때문에 재사용 금지 |

### 작업관리 연동의 실제 흐름

1. 공개 폼 제출 시 상담 또는 용지 요청 문서가 Firestore 접수 컬렉션에 저장된다.
2. 백오피스 `BackConsultations.tsx`에서 관리자가 담당자·일정 등을 정한다.
3. 관리자가 등록 동작을 실행하면 `buildConsultationTask` 또는 `buildPaperRequestTask`로 작업이 생성된다.
4. 트랜잭션 성공 후 원래 요청 문서에 `linkedTaskId`가 기록된다.

따라서 현재 공개 문구인 `작성 즉시 작업관리 화면에 연결`과 `접수 내역 작업관리 연동`은 자동 일감 생성으로 오인될 수 있다. 권장 문구는 `접수함에 저장되며 담당자 확인 후 작업으로 등록됩니다`이다.

## 10. 즉시 수정 우선순위

1. `WebsiteBlockRenderer.tsx`의 빈 가격 `0원` 폴백을 공개하지 않도록 차단
2. U+AI전화 페이지의 `18건`, `94%`, 가상 시간·문의 기록 등 임의 수치 숨김
3. 공개 폼의 `작성 즉시 작업관리 연결`을 `접수함 저장 후 담당자 확인`으로 수정
4. 모든 `무료`, `무상`, `0원`, `34,000원`, `43,000원`, `100%`, `최고` 문구를 확인 전 숨김
5. U+AI전화 `24시간`에 가입·설정·응대 범위 조건 추가
6. CCTV 긴급출동에 대상 상품·월 제공 횟수·추가 비용 조건 추가
7. `안산·경기권 현장 지원`, 설치·교육·AS 범위와 비용을 사업자 확인 전 조건부 문구로 축소
8. 패키지 제품 목록을 `구성 예시`로 명시하고 판매·임대·증정 오인을 제거
9. `공식 이미지` 표현을 권리와 출처가 확인된 에셋에만 사용
10. Firestore에 저장된 CMS 문구를 내보내 동일 키워드와 분류 기준으로 재감사
